# Measure Thrice, Cut Once

I measure an extra time because I am cautious.

# Humility in Architecture is the key to Sturdy Design
The more rocks you throw at my design, the sturdier the implementation _should_ be.

- [ ] Does it Solve the Requirement
- [ ] Does it add Technical Concerns the muddy the Solving of Requirements?
- [ ] Do simple changes to the Domain require many complex changes to the corresponding code?

# Breaking my design is cheaper than breaking my implementation
As a Steward of the Businesses coffers, I should strive to ensure that what I deliver is efficient, maintainable, and solves the requirements the steakholders provide.  If I have a team of people work for a sprint and throw a bunch of code at a problem, and it doesn't work, I have wasted the Business' time and money.
